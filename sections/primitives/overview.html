Primitives Overview

Primitives are unstyled, single-responsibility layout containers that consume the design tokens. They express a layout intent — vertical rhythm, a wrapping row, a centered column — instead of a single property, and sit between utilities and components in the system: tokens → (utilities | primitives) → components.

The composition ladder

Each layer is built from the one below it. You can drop down a layer at any time — primitives never trap you.

Tokens — named values (--vd-space-fib-13, --vd-bg-secondary). The vocabulary.
Utilities & Primitives — utilities style one element (.vd-p-6); primitives arrange elements (.vd-stack). Siblings that consume tokens.
Components — skinned, often interactive UI (.vd-card, .vd-modal) built from primitives + tokens.

Utilities vs primitives — when to use which

The rule of thumb: utilities style an element; primitives arrange elements. A primitive replaces a recurring cluster of layout utilities with one intent-named element.

Scope — and what is intentionally not a primitive

Vanduo ships a deliberately focused set of layout primitives: Box, Stack, Inline, Center, Frame, Cover, and Switcher. They are CSS-only with a data-* API and add no new public tokens. Frame defaults to the golden ratio; Switcher flips a row to a stack at a Fibonacci threshold with no media query.

Deferred on purpose (already covered elsewhere, so a primitive would only add overlap):

  • Grid — use the existing Grid System and Golden Ratio layouts.
  • Spacer / Divider — covered by spacing utilities (.vd-mt-*, .flex-1) and borders.
  • Text — covered by the typography scale and .vd-text-* utilities.

Vanduo is CSS-first, so there are also no headless behavior primitives — interactive behavior lives in components.
